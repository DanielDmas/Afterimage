  - `event_bus.gd` — typed pub/sub, registration-order dispatch, non-reentrant (queued) re-publish, snapshot-iterated so a handler unsubscribing itself mid-dispatch is safe (foundation_blueprints §1.2).

- **Test harness** (`tests/framework/`, `tests/run_tests.gd`): a small custom xUnit-style harness (`AfterimageTestCase`, `AfterimageTestRunner`) — **not GUT**. See the decision note below.
- **67 unit tests** across 5 files (`test_fixed_math.gd` 15, `test_prng.gd` 10, `test_event_bus.gd` 11, `test_predicate_evaluate.gd` 20, `test_predicate_validate.gd` 11), plus a reusable `MockWorldQuery` test double in `tests/framework/`.
- **CI** (`.github/workflows/ci.yml`): a `test` job that downloads Godot 4.3-stable headless and runs the suite, and a `lint` job running `gdlint`/`gdformat --check`.
- **Title change**: the game is now titled **Afterimages: Vranov** (README, master_plan.md header + §12 risk resolved, tech_guidelines.md amendment log). The in-fiction mechanic keeps its original name, "the Afterimage."

**Decision — custom test harness instead of GUT (tech_guidelines.md §12 amendment):** `tech_guidelines.md` D13 locked in GUT. GUT has to be fetched from GitHub — as a git submodule or via the editor's AssetLib — and this authoring sandbox has no network path to GitHub (confirmed: `git`/`curl` to `github.com` return a policy-level 403 from the egress proxy, and `git submodule add` needs to resolve a real commit hash from the remote, which isn't possible offline). Rather than block Pass 1 on that or hand-copy a third-party project's source from memory, I built a small in-house harness whose assertion surface (`assert_eq`, `assert_true`, `assert_almost_eq`, …) deliberately mirrors GUT's naming, so adopting real GUT later — once someone with GitHub access pins a commit via submodule — is an addition, not a rewrite of any test file. Recorded as a proper amendment in `tech_guidelines.md` §12, not a silent deviation.

**Verification approach and its honest limits:** this sandboxed environment has no Godot binary and no working Docker daemon, so nothing in this pass has been executed inside the actual Godot runtime by me directly. Given that constraint, verification leaned on everything that *was* available:
1. **The PRNG is the highest-risk piece** (hand-porting 64-bit-unsigned bit-twiddling algorithms into a 64-bit-*signed* scripting language). Rather than trust the port by inspection, I wrote an executable Python reference implementation of splitmix64 + xoshiro128**, ran it to generate concrete output vectors for five seeds, then wrote a *second* Python model that mimics GDScript's exact arithmetic assumptions (signed 64-bit wraparound, arithmetic right-shift, explicit unsigned-shift correction via precomputed masks) and confirmed it reproduces the canonical vectors bit-for-bit before porting that exact logic to GDScript. The five seeds' first-12-draws are pinned directly into `test_prng.gd` as `VECTORS`. The one assumption that couldn't be verified without a real Godot process is that GDScript's `int` actually performs silent two's-complement wraparound on overflow and that `>>` is arithmetic — both are documented Godot 4 behaviors, and the test is written so that if either assumption is wrong, CI's real headless Godot run will fail loudly on `test_reference_vectors_match_across_seeds` rather than silently producing subtly-wrong randomness.
2. **`gdtoolkit` (gdlint/gdformat) was installed and actually run locally** (`pypi.org` is reachable through this session's egress policy even though `github.com` isn't) — every source and test file was run through `gdformat --check` and `gdlint` and is 100% clean, which catches real syntax errors, not just style: gdformat has to fully parse a file's GDScript grammar to reformat it, so a clean run is meaningful evidence the code is at least syntactically well-formed.
3. **GDScript closure semantics were treated as a known trap, not assumed**: GDScript lambdas capture outer local variables *by value*, not by reference, so a naive `var count := 0; bus.subscribe(..., func(e): count += 1)` pattern would silently produce a false test failure (the outer `count` never changes) that has nothing to do with whether `EventBus` itself is correct. Every `EventBus` test that needs a mutable counter across calls uses a small helper class with a bound `Callable(instance, "method")` instead, sidestepping the issue entirely.
4. **What's *not* verified yet**: actual execution inside Godot. The first real Godot run happens in CI on push (GitHub Actions runners have full internet access regardless of this sandbox's restrictions), and I will check that run's logs via the GitHub API/MCP tools immediately after pushing and fix forward in a follow-up commit within this same pass if anything surfaces — this is called out explicitly rather than assumed clean.

**Deferred to Pass 2** (see `roadmap.md` M0): `GameStateStore`, `SaveSystem` + schema/migration harness, the fixed-tick simulation harness, `InputFrame` recording/replay, and the determinism corpus + its CI job. M0's actual exit criterion ("inputs recorded in a stub scene replay tick-perfect") is **not yet reached** — Pass 1 built the deterministic primitives that harness will be built on top of, not the harness itself.

**Post-push CI verification (the loop this whole approach depends on):** first real CI run ([run 29654915740](https://github.com/DanielDmas/Afterimage/actions/runs/29654915740)) came back **lint: pass, test: fail** — checked via the GitHub Actions API, not assumed. The good news first: `gdlint`/`gdformat --check` passing for real on GitHub's infrastructure confirms the local `gdtoolkit` run in this pass was meaningful, not just theater. The failure was real and unrelated to any of the PRNG/overflow risk called out above — it was simpler and more fundamental:

```
SCRIPT ERROR: Parse Error: Could not find type "AfterimageTestRunner" in the current scope.
  at: GDScript::reload (res://tests/run_tests.gd:11)
```

**Root cause:** `.godot/` (Godot's project-scan cache, which is where global `class_name` → script-path resolution gets recorded) is correctly gitignored — it's a local editor artifact, not something to commit. But that means on a genuinely fresh checkout, Godot hasn't scanned the project yet, so none of this pass's `class_name` globals (`AfterimageTestRunner`, `FixedMath`, `Xoshiro128StarStar`, etc.) are resolvable the moment `--script res://tests/run_tests.gd` tries to parse a reference to one. Opening a project in the editor UI triggers this scan invisibly and automatically; running a script directly via `--headless --script` does not.

**Fix:** added an explicit one-time import pass — `godot --headless --path . --editor --quit` — before running the test script, in both `.github/workflows/ci.yml` and the README's local instructions. This forces the same project scan the editor would do on first open, without needing a display. Its own exit code is treated as non-authoritative (`|| true`) since a benign warning can make that pass itself report nonzero; the test-running step right after it is what actually gates the build, and it now starts from a warm class-name cache. This is exactly the verification loop described as the plan for this pass: something unverifiable locally (real Godot script-loading behavior on a cold checkout) surfaced through real CI, got diagnosed from the actual error text rather than guessed at, and was fixed forward in the same pass rather than discovered later.

**Confirmed green** ([run 29655073102](https://github.com/DanielDmas/Afterimage/actions/runs/29655073102), commit `a788729`): both jobs `success`. Pulled the actual test-step log text rather than trusting the exit code alone —

## Pass 2 — GameStateStore, SaveSystem, fixed-tick harness, determinism corpus v0

**Delivered** (all under `src/core/`, engine-agnostic `RefCounted` classes, no scene-tree dependency, matching Pass 1's discipline):
- **`save_migrations.gd`** — the migration ladder (foundation_blueprints.md §6). `CURRENT_SCHEMA_VERSION = 2`, deliberately not 1: a real v1→v2 step is registered and exercised (v1 stored `day`/`flags` at the save's top level; v2 nests them under `campaign`), dispatched via a `match` statement rather than a self-referential `static var` dictionary of `Callable`s — the dictionary-of-callables version would have worked too, almost certainly, but it rests on an assumption about static-initializer ordering during self-referential class loading that I can't verify without running Godot, and the `match` version has no such assumption at all. Given the choice, the one with zero unverifiable assumptions won.
- **`game_state_store.gd`** — single serializable source of truth (blueprints §1.1): key-path `get_value`/`set_value` over a private `Dictionary`, `to_dict()`/`load_from_dict()` with migration on load. "All mutations are Events" is satisfied by `set_value()` publishing a `StateValueChanged` fact (old/new value) on the EventBus rather than by full event-sourced state reconstruction — that stronger guarantee is reserved for TruthSim's tick log, which is what actually has to survive re-simulation. Documented this distinction explicitly in the class doc so it doesn't read as an oversight later.
- **`save_system.gd`** — JSON + gzip persistence (tech D8/§5.3) via `PackedByteArray.compress()`/`decompress()` with `FileAccess.COMPRESSION_GZIP`. Decompression reads the required output-size hint from the gzip stream's own trailing ISIZE field (RFC 1952 §2.3.1: last 4 bytes = uncompressed size mod 2^32, little-endian) instead of inventing a custom header — this is externally-verifiable knowledge (the gzip spec itself, not a Godot-specific guess), and it means a save this writes is a genuine standalone `.gz` file, not a wrapper format. The one real assumption — that Godot's `COMPRESSION_GZIP` mode actually emits RFC 1952-framed output (magic bytes `0x1F 0x8B`, real trailer) rather than something merely similarly-named — is asserted directly in `test_save_system.gd::test_save_produces_a_valid_gzip_stream`, so a wrong assumption fails loudly in CI rather than silently corrupting saves.
- **`input_frame.gd`, `replay_log.gd`, `fixed_tick_clock.gd`** — the fixed-tick contract (tech §3.1): `InputFrame` is a generic `String -> Variant` action map (deliberately not tied to concrete verbs yet — InputMap actions land with combat in Pass 6), `ReplayLog` is the versioned seed+frames stream that later becomes both the mission save and the Theater's source, `FixedTickClock` is the 30 Hz whole-tick counter TruthSim will use instead of reading engine `delta`.
- **`tests/fixtures/stub_sim.gd`** — an explicitly disposable placeholder for TruthSim, folding PRNG + FixedMath + a toy position/accumulator over a replay's frames into a SHA-256 digest via `HashingContext`. Lives under `tests/fixtures/`, not `src/`, because it will be deleted the moment Pass 3's real TruthSim exists to test against instead.
- **`tests/corpus/run_00{1,2,3}.json`** — three recorded fixture runs (5/8/12 frames, distinct seeds), the "determinism corpus v0" roadmap.md asks for.
- **44 new tests** across 7 files (`test_input_frame` 6, `test_fixed_tick_clock` 6, `test_replay_log` 5, `test_save_migrations` 5, `test_game_state_store` 10, `test_save_system` 6, `test_determinism_corpus` 6), bringing the suite to 111 tests. All clean against `gdlint`/`gdformat --check` locally before commit (same discipline as Pass 1).

**On the determinism-corpus acceptance criterion, honestly scoped:** roadmap.md's M0 item reads "re-simulates hash-identical on Linux/Win/mac in CI." What Pass 2 actually proves is narrower and stated as such in `test_determinism_corpus.gd`'s header comment: the record→replay→hash→compare *mechanism* correctly detects both agreement (same fixture replayed twice ⇒ identical digest) and divergence (`test_digest_is_sensitive_to_an_extra_frame`, `test_digest_is_sensitive_to_run_seed`) — in-process, on one OS. I deliberately did not hand-write "golden" expected digest values into the corpus fixtures: I can't execute Godot here to compute them, and fabricating expected SHA-256 values by hand-reasoning about the stub sim's arithmetic would risk baking in *my* mistake as the "correct" answer rather than testing anything real. Self-consistency (replay twice, compare) sidesteps that risk entirely while still proving the property that actually matters. True cross-platform (Linux/Windows/macOS) byte-identical agreement — and a dedicated PR-subset-vs-nightly-full CI split — stay open, tracked in roadmap.md alongside the Windows/macOS runner gap already noted from Pass 1; both are deferred until there's a real multi-OS matrix and a corpus large enough to make the PR/nightly split matter, rather than built ahead of the need.

**Post-push CI verification:** [run 29662878857](https://github.com/DanielDmas/Afterimage/actions/runs/29662878857) came back **lint: pass, test: 110/111 pass**. The good part first: both gzip assumptions this pass carried were confirmed correct on real Godot — `test_save_produces_a_valid_gzip_stream` (RFC 1952 magic bytes) and `test_save_load_save_is_byte_identical` both passed, so `COMPRESSION_GZIP` really does emit standard-framed gzip and the ISIZE-trailer decompression technique works as designed.

The one failure was a test bug, not a system bug: `test_save_and_load_round_trip_preserves_state` asserted `loaded.to_dict() == store.to_dict()` and failed with identical keys/values in different order (`{"schema_version", "campaign"}` vs. `{"campaign", "schema_version"}`). Reasoning from both results together (this failure plus the adjacent byte-identical test passing) points at `JSON.stringify()` canonicalizing key order on output independent of a Dictionary's insertion-order history: the byte-identical test's two sides both pass through `stringify()` as their last step and land on the same canonical order regardless of their respective in-memory history, which is exactly why *that* test is order-*in*sensitive while a bare `to_dict() == to_dict()` comparison across one JSON round-trip is not. Dictionary key order was never a real correctness requirement here — only that values survive the round trip — so the fix was to assert the specific values via `get_value()` instead of whole-Dictionary equality, which is both a more precise test of intent and immune to the ordering question entirely. Re-verified clean against `gdlint`/`gdformat --check` locally before pushing the fix.

## Pass 3 — TruthSim actor model: entity IDs, grid collision, swept casts

**Delivered** (all under `src/sim/`, per tech_guidelines.md §5.8's repo layout — the first files in that directory):
- **`actor.gd`, `actor_registry.gd`** — a truth-layer body (position + collision-circle radius) and its registry, assigning sequential entity IDs (tech §3.5 — never a Godot object instance ID, which isn't stable/reproducible across runs). Deterministic iteration via a sorted `all_ids()`.
- **`collision_grid.gd`** — a sparse uniform grid of blocked/free cells (a `Dictionary`, not a fixed-size array): no real level exists yet (the Pass 7 graybox room), so there's nothing to size a dense grid against, and a sparse one needs no upfront bounds. Correctly floors world coordinates to cell indices for negative coordinates too — GDScript's bare `/` truncates toward zero (C semantics), which is the wrong operation for a floor-based grid index, so `_floor_div()` corrects it explicitly (tested against negative-coordinate cases).
- **`swept_collision.gd`** — the actual "swept casts" tech_guidelines.md §3.4 asks for: swept circle-vs-AABB via the Minkowski-sum slab method (expand the static box by the circle's radius, sweep the circle's center as a point against the expanded box). Every arithmetic case — straight hit, parallel-and-outside, too-short-to-reach, already-overlapping (reports t=0), diagonal hit, moving away, exact-endpoint touch, and both zero-delta edge cases — was worked out first in an executable Python reference using exact `Fraction` arithmetic, the same "verify externally with a tool that isn't Godot, then port" discipline as Pass 1's PRNG. One deliberate, documented simplification: box corners are treated as square, not rounded (a true rounded-corner sweep needs a quadratic/sqrt solve per corner, which buys very little collision-feel difference for a top-down action game over the square-corner approximation). Actor-vs-actor collision only gets a *static* overlap test (`circles_overlap`, exact integer distance-squared, no sqrt) — true swept circle-vs-moving-circle collision is deferred until multiple simultaneously-moving bodies actually need it (AI in Pass 5+), not built ahead of that need.
- **`fixed_math.gd` gained `to_int_trunc()`** — truncates toward zero for both signs, needed because `move_with_collision()`'s existing `to_int_floor()` would over-shoot a stopped movement further in the negative direction for negative deltas (flooring a negative fraction rounds *away* from zero, which is exactly wrong for "stop at or before the impact point" semantics regardless of travel direction).
- **`truth_sim.gd`** — the tick orchestrator: one player `Actor`, `step(InputFrame)` reads `move_x`/`move_y` as a raw per-tick millimeter delta and resolves it through `SweptCollision.move_with_collision()` against the grid, publishing `ActorMoved` only when a move actually changed position. Deliberately narrow scope: no AI, no combat, no witnesses (Pass 5/6/4 respectively) — this is the foundation those passes build onto, and `step()`'s signature (one tick, one InputFrame) is meant to stay stable as they plug in.
- **39 new tests** across 4 new files (`test_actor_registry` 6, `test_collision_grid` 7, `test_swept_collision` 16, `test_truth_sim` 9) plus one addition to `test_fixed_math` (`to_int_trunc`), bringing the suite to 150 tests. All clean against `gdlint`/`gdformat --check` locally before commit.

**Scoping decision — the corpus stays on StubSim, not TruthSim, for now:** Pass 2's dev_log entry said "delete `stub_sim.gd` once TruthSim lands and the corpus points at that instead." On reflection, doing that *now* would make the corpus mechanism *less* representative, not more — a movement-only TruthSim with no walls in most fixtures has no more interesting divergence surface than the toy StubSim already proves against. `test_determinism_corpus.gd` and its 3 JSON fixtures are left untouched; TruthSim instead gets its own direct correctness tests (exact expected positions, not opaque hash comparisons), which is a better fit for verifying *this* kind of behavior anyway — collision outcomes are things I can and did work out exactly by hand/Python, not just check for reproducibility. Revisiting "point the corpus at real TruthSim" is deferred until AI and combat (Pass 5/6) give it enough real behavior to be worth the swap. Noted here as the kind of plan adjustment the top of this log already allows for ("later passes may adjust it as real constraints surface").

## Pass 4 — Line-of-sight and sound propagation

**Delivered** (`src/sim/`, continuing Pass 3's foundation):
- **`line_of_sight.gd`** — `cells_along_line()` implements Bresenham's line algorithm (the standard integer-only err/e2 formulation, symmetric across all octants), verified against an executable Python reference across nine cases (horizontal, vertical, diagonal, both shallow and steep slopes, both negative directions, a single point, and a reversed-direction check) before porting. `has_clear_line()` builds on it against `CollisionGrid`'s existing blocked-cell data — deliberately *not* a second parallel occlusion grid, since wall geometry blocking movement and wall geometry blocking vision is the same geometry, and maintaining two copies would just be duplicated data with no behavioral upside. The two endpoints' own cells are exempted from the blocking check (an actor standing in a doorway, or anywhere else, shouldn't have their own occupied cell block their sightline).
- **`sound_graph.gd`** — an abstract room/portal graph (rooms are opaque string IDs; no real level exists yet). A sound's loudness is a subtractive integer budget that portals attenuate when crossed; `propagate()` finds the *loudest possible* arrival at every reachable room — a shortest-path problem (minimize total attenuation) — via iterative relaxation rather than a priority-queue Dijkstra, since real room graphs will be small (tens of rooms, not thousands) and relaxation is simpler to get right and to verify than a heap-based implementation. A room every path attenuates to ≤0 is *omitted* from the result, not present at 0 — tested explicitly, along with a case where a longer, less-attenuating path must win over a shorter, noisier direct one.
- **26 new tests** across 2 new files (`test_line_of_sight` 14, `test_sound_graph` 12), bringing the suite to 176 tests. Clean against `gdlint`/`gdformat --check` locally before commit.

**Scoping decision — no vision cone yet:** master_plan.md describes AI senses as "vision cones, sound propagation, last-known-position memory" (§5.5), and it was tempting to build the angular field-of-view wrapper (range + half-angle around a facing direction) as part of this pass. I started working through the math — an angle-free cone test using squared dot products to avoid `atan2`/`sqrt` in sim code (per tech_guidelines §3.2's "no ad-hoc float math") is workable, but only if the facing-direction vector is a small normalized magnitude rather than a raw world-space displacement, or the intermediate `dot²` and `|a|²·|b|²` terms overflow int64 — and even done carefully, it's a nontrivial piece of arithmetic with no actual caller to verify it against yet. The roadmap and dev_log's own Pass 4 scope only ever named "line-of-sight + sound propagation," not vision cones; that phrase belongs to Pass 5 (Sentry/Professional AI), which is where it has a real consumer and a real test (does this specific archetype notice the player in this specific scenario). Deferred there rather than built speculatively now.
